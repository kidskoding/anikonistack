# uv Pull Requests

## Overview

Overlay for astral-sh/uv. Where this file and `creating-pull-requests` disagree, this file wins.

**REQUIRED BACKGROUND:** `creating-pull-requests`. Run its Steps 1 to 4. This file supplies the uv-specific answers so Step 1 costs one read instead of four, and replaces Step 5.

## Astral AI policy: the deliverable is a facts sheet

`CONTRIBUTING.md` links `astral-sh/.github/AI_POLICY.md`. It requires the PR body and every reply to maintainers to be in the contributor's own words, and closes PRs it believes were opened autonomously.

Consequences, no exceptions:

- Output ends at the facts sheet from `creating-pull-requests` Step 4. Present it to the user. The user writes `## Summary` and `## Test Plan`.
- Never run `gh pr create` or `git push` for a uv branch. Print the commands. The user runs them.
- No AI footer, no `Co-Authored-By: Claude`, no `codex-thread` comment in anything the user submits.
- Never draft a reply to a review comment. Summarize what the reviewer asked and which code it points at. The user answers.
- The policy requires a human who understands the work. The facts sheet opens with a hunk walkthrough (below). The user confirms they can explain each hunk before writing the body. A hunk the user cannot explain does not ship.

## House rules (pre-read, verified 2026-09)

| Rule          | Value                                                                                                                                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Remotes       | `origin` = fork (`kidskoding/uv`), `upstream` = `astral-sh/uv`. Diff against `upstream/main`, not `origin/main`.                                                                                                                |
| Template      | `.github/PULL_REQUEST_TEMPLATE.md`: `## Summary` then `## Test Plan`. Keep both headings verbatim.                                                                                                                              |
| Title grammar | Imperative, capitalized, no `type:` prefix, no trailing period, backticks around identifiers. Examples from `main`: `Reject invalid Git archive paths in lockfiles`, `Avoid writing lockfiles when reading workspace metadata`. |
| Changelog     | Generated by rooster from PR labels (`pyproject.toml` `[tool.rooster.section-labels]`). Maintainers apply labels. Title becomes the changelog line, so it must read as a user-facing change.                                    |
| Issue policy  | `help wanted`, `good first issue`, `bug`: go ahead. `needs-design`, `needs-decision`: no PR. Feature with no prior maintainer discussion: no PR, it gets closed.                                                                |
| Docs          | `docs/reference/cli.md` is gitignored and generated. Other docs under `docs/` are hand-written and get committed.                                                                                                               |

## Gates

Run in this order. Record exit codes. Skip nothing silently.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo dev generate-all --mode dry-run
uv run --only-group=check typos
cargo nextest run -E 'test(<name of each test touched or added>)'
```

Snapshot tests use `insta`. A changed snapshot is reviewed, not blindly accepted:

```bash
cargo insta test --accept --test-runner nextest -- <test_name>
git diff --stat   # every .snap change must be explainable in the facts sheet
```

Integration tests live in `crates/uv/tests/it/`. They need managed Pythons: `cargo run python install`. A test that needs a Python you lack is reported `NOT RUN (missing Python 3.x)`.

Full workspace `cargo nextest run` is a cold multi-minute build. Run the touched tests locally, state that CI runs the rest. Do not claim the suite passed.

## Facts sheet additions for uv

Prepend to the standard sheet:

```
HUNK WALKTHROUGH
  <path>:<line>  <what changes, one clause>  <why, one clause>
  ...one row per hunk, no hunk skipped
```

Append to the standard sheet:

```
LABEL SUGGESTION  <one of: bug | enhancement | documentation | performance | internal | area:...>
SNAPSHOTS CHANGED <list of .snap files with one-line reason each, or "none">
PYTHONS USED      <versions the touched tests ran against>
```

## Gotchas

- **The facts sheet is not a draft body.** Baseline agent produced a full `## Summary` with an AI footer in this repo after reading the policy. Facts sheet is bullet facts. Prose is the user's job.
- **`VersionFormat`-style shared enums serve multiple commands.** Help text in `crates/uv-cli/src/lib.rs` is often shared between `uv <cmd>` and `uv self <cmd>` or `uv pip <cmd>`. Grep every use site before describing behavior in a docstring.
- **`origin/main` on a fork is stale.** `git fetch upstream` then compare against `upstream/main`. A branch that is "0 behind origin/main" can be 40 behind upstream.
- **A comment-only Rust diff still runs `cargo fmt --all --check`.** rustfmt reflows doc comments over 100 columns.
- **`cargo dev generate-all` drift is a CI failure, not a warning.** Changes to settings structs, environment variables, or the JSON schema regenerate committed files. Run the dry-run gate every time. A clap docstring change alone produces no drift: its only output is the gitignored `docs/reference/cli.md`.
- **Any `println!`/`eprintln!`/`dbg!` left in the diff is a clippy error, not a warning.** Workspace `Cargo.toml` sets `print_stdout`/`print_stderr` to warn and CI runs clippy with `-D warnings`. Grep the diff for them before the cold clippy build.
- **`test:*` and `build:*` labels are maintainer switches.** Never suggest them. They enable extended CI, not categorization.
